# Course Philosophy

## Thinking Is the Skill

Programming languages change.  
Tools evolve.  
AI improves rapidly.

The ability to **think clearly about a problem** remains constant.

This course is built on a simple principle:

> Code is not the skill.  
> Thinking is the skill.

Software exists to express solutions—not to replace understanding.

---

## Problem First, Code Second

Many programming resources start with syntax.

This course starts with the problem.

The process used throughout the course is:

1. Understand the problem  
2. Define inputs and outputs  
3. Design a solution  
4. Choose the right tool  
5. Implement with code  

Code is introduced **after** the problem is clear.

---

## Experience Is a Mindset

The difference between less experienced and more experienced practitioners is not speed or syntax.

It is focus.

Less experienced approaches often center on:
- Writing code quickly
- Choosing tools first
- Relying on generated solutions

More experienced approaches focus on:
- Understanding constraints
- Making trade-offs
- Selecting tools intentionally
- Using automation to support reasoning

This course is designed to develop the second approach from the start.

---

## AI as a Support Tool

AI is a powerful tool and is treated as such in this course.

AI may be used to:
- Explore ideas
- Generate examples
- Assist with implementation

AI should not be used to:
- Define the problem
- Replace reasoning
- Skip design decisions

If the solution is not understood, AI output has little value.

---

## How to Use This Course

This course is not meant to be rushed.

For each topic:
- Read the problem carefully
- Think about the solution before writing code
- Use paper, diagrams, or plain language first
- Implement only after your approach is clear
- Use AI **after** you understand what you are building

Progress is measured by clarity of thinking, not lines of code.

---

## The Goal

The goal is not to produce experts in a specific language.

The goal is to help anyone:
- Approach problems methodically
- Use software with intention
- Adapt to new tools confidently

Once thinking is clear, tools are easy to learn.

That is the foundation of **Problem First Programming**.
